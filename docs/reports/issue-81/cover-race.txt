# Cover race — evidence

Cause: `reloadVisibleHistory` read a page with `artwork_hash` nil and then
awaited `count`, `hasOlderListen` and `hasNewerListen`. If `attachArtwork` and
`updateVisibleListens` filled the visible row during those awaits,
`applyHistoryPage` replaced it with the stale nil row. When the artwork task
had already filled its one row (or the captured row was not on the page yet),
nothing filled it again that session. The failure is a lost update, not a slow
write; the 10-second wait and `.serialized` only masked it.

Deterministic test: `CaptureArtworkTests.aStalePageCannotEraseAKnownCover`.
A real SQLite store is wrapped so its page reads strip the artwork hash. The
test reloads and appends while the state already knows the cover.

After the fix: the runtime records resolved covers by raw track identity in

`loadMoreHistory`, `loadNewerHistory` and both track-history page assignments.
The test passes, and `CaptureArtworkTests` has no widened wait and no
`.serialized` trait.
